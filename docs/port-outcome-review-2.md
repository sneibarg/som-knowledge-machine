# Where the port still differs after the wrap-up

[The outcome review](port-outcome-review.md) is unchanged. It records the ten wrap-up steps, and those steps are done. This note reads the migration notes again, except [the Maven library note](migration/21-maven-library.md), and sorts what is still open.

An early note describes the engine at that step. A later note takes a difference back when it says the behavior now runs. The sentences below are the ones no later note takes back. `plan.md` is the list of differences that come from Lisp and Clojure themselves. A difference in that list stays even when every handler runs.

Two groups follow. The first is Knowledge Machine behavior this port does not yet do, and Clojure can do it. The second is a difference that remains while the engine is Clojure, with the reason a further port does not remove it.

## What can still be addressed

These change an answer, a frame, a printed line, or a file. Each one is ordinary Knowledge Machine behavior. Nothing in the language blocks it.

**`(anonymous-instancep ...)` stops a file.** The predicate asks the frame store and follows a binding. [Patterns, lists, and equality](migration/02-patterns-lists-and-equality.md) left it out. [The remaining commands](migration/25-the-remaining-commands.md) left it refused. `Entity.km` still stops on that call. `(has-value ...)` already runs, so this predicate is the stop that file still hits.

**An action precondition stops the action.** A ground precondition goes through `(frame is '(a Thing with ...))`. A description with slots comes back as a refusal, so the action stops. An unsatisfied precondition would let the action continue. [Situations, actions, and theories](migration/12-situations.md) records that path. [Definitions and classification](migration/17-definitions-and-classification.md) and [Rule bodies](migration/18-rule-bodies.md) still record it.

**A few explanations cite a different record.** A binding copies the bound-away frame's records onto the survivor and leaves that frame in place. The Lisp deletes the frame. [The same explanation](migration/23-the-same-explanation.md) records the copy and the frame that stays. `(explained-by ...)` stays refused, and a cached explanation is not stored. `originated-from-classes` does not walk a prototype triple through `in-prototype`. `(result-of ...)` and `(precondition-for ...)` are stored, and `(why)` prints them as `(|<location unknown>| ...)`.

**Classification still skips some of the Lisp calls.** [Definitions and classification](migration/17-definitions-and-classification.md) records each of these. The description is tested as `(a Class with ...)`, with the instance's current class as the head. The Lisp head is Thing. The fallthrough in [One survivor](migration/22-one-survivor.md) now answers `(Thing subsumes Cat)`, so that head can be used. Slots named by `slots-to-opportunistically-evaluate` are not read at creation. A class that has not been declared draws no warning. Installing an inverse does not classify the other frame. `(evaluate-paths)` does not classify the clones it builds. A load in prototype mode does not run the constraint pass. A number in that batch is skipped, and the Lisp records that a number is not a knowledge-base object. A `SETQ` of `*RECURSIVE-CLASSIFICATION*`, `*INDIRECT-CLASSIFICATION*`, or `*CLASSIFY-SLOTLESS-INSTANCES*` inside `load-kb` is not accepted. The three flags stay at their defaults, which are all true.

**The subsumption search drops one probe.** [Subsumption](migration/08-subsumption.md) searches the object stack. The inverse read `(the Class invslot of value)` is refused, that refusal is discarded, and the search continues.

**An appending slot takes the first shared source.** [One survivor](migration/22-one-survivor.md) joins values that share a cloned source. The Lisp scores every permutation of the two lists before it pairs them. This pass takes the first shared source. The two Lisp lists that can block the heuristic start empty and are not consulted. A different pairing changes which values merge.

**A class cycle throws.** A class stored as its own subclass throws on `(the subclasses of Cat)` and on `(the all-subclasses of Cat)`. The `has` that stored the link still answers `(Cat)`. The Lisp reports the cycle and continues with the name removed. A subslot cycle throws the same way. [One survivor](migration/22-one-survivor.md) records the class cycle.

**`(sanity-check ...)` leaves its body unread.** The flag starts unset, and the answer is `(t)`, which is the Lisp answer while the flag is unset. [Stored flags](migration/20-stored-flags.md) records that. Turning the flag on, and then running the body, is the part that is still open. `(clean-taxonomy)` at the prompt stays refused. `(taxonomy)` already runs the cleanup. `(clear-situations)` stays refused.

**Printed lines that the Lisp writes are still quiet.** Each of these is a sentence the notes say is absent. The trace menu itself is in the next section. The finer classify, unify, constraint, and other-situation comments are not printed. The comments inside the loop handler are not printed. A name lookup that keeps the first name does not print its comment. A prototype participant stored from another situation does not record the Lisp warning. Several values of `prev-situation` keep the first value and do not print the warning. `unquote` of a value that is not quoted, an `&` longer than three elements, and `val-sets-to-expr` continue without the Lisp warning line. The KM 1.4 fluent-status banner is not printed. [English text and the taxonomy listing](migration/14-english-and-taxonomy.md), [Trace, statistics, the event-chain walker, and the licence](migration/15-trace-statistics-sadl-and-license.md), [Prototypes](migration/10-prototypes.md), [Situations, actions, and theories](migration/12-situations.md), and [Patterns, lists, and equality](migration/02-patterns-lists-and-equality.md) record these.

**Undo and the stored snapshot differ in ways a log can match.** [Load, save, and undo](migration/13-load-save-and-undo.md) restores the snapshot, including the done flags. The Lisp replays the logged commands and then clears those flags. `undo-creations` does not take a dont-delete list and does not return to `*Global`. `store-kb` keeps the undo history on the value. The Lisp snapshot omits that log. A knowledge-base access counts one successful `get-vals`. The Lisp counts one `getobj`. A top-level query zeroes the port's counter, so two values can differ in that counter when the frames are the same.

**A deleted built-in name becomes unknown.** [Built-in vocabulary and reset](migration/04-built-in-vocabulary-and-reset.md) answers `known-frame?` from membership in this knowledge base. Deleting `Thing` makes it unknown until the next `reset`. The Lisp still answers from the name list. `class?` and `slot?` already use that list.

**`(update-subclasses-of-thing)` is defined and is not called.** [The same file](migration/24-the-same-file.md) records the partition warning and leaves an unplaced class without a stored superclass. The superclass query already answers through the fallthrough. Calling the function would store the link.

**A few texts were left on purpose, and each one can be switched.** [Trace, statistics, the event-chain walker, and the licence](migration/15-trace-statistics-sadl-and-license.md) prints the repository `LICENSE` file. `licence.lisp` still has the older body, 1994–2011 and `peterc@vulcan.com`. A save omits `(now)`, so two saves of one value match. [The small texts](migration/26-the-small-texts.md) leaves the session banner as the prompt's own text. `(version)` prints the `initkb` banner when a transcript calls it. Loading the engine does not print that banner as well. `#t` compares the name in uppercase, so `#t|Foo|` matches a binding stored as `foo`. [Read and print](migration/01-read-and-print.md) records that fold.

## What Lisp and Clojure cannot share

These stay while the engine is Clojure. A handler can imitate the answer around them. It cannot remove the cause.

**There is no Common Lisp image to evaluate.** `*km-lisp-exprs*` includes names the Lisp `eval`s. `(function ...)` is a Lisp function. `(eval ...)` and `(SETQ ...)` at the prompt are Lisp. A custom aggregation is a Lisp function. `#.` and `#=` would evaluate while reading, and the reader refuses them. `#t` in the Lisp reads a variable from the package that was current outside `#$`. This image has no such package. `#t` looks in a map the caller supplies. The prompt and HTTP pass an empty map, so a file that splices a live Lisp variable does not load. `fastsave-kb` writes `setq` forms for symbol property lists. `fastload-kb`, `faslsave-kb`, and `load-newest-kb` read that image back. Clojure has no Common Lisp `eval`, no symbol property lists, and no fasl. The `.km` text `save-kb` writes is the round trip that can work. Implementing those four commands means implementing Lisp.

**The debugger and its restarts are not a library.** `debug` and `break` enter the Lisp debugger. The trace menu reads `g`, `r`, `a`, `o`, and `A`, and a person resumes the same stack. Clojure has no restart. The port records the error, continues for `continue` and `ignore`, and stops for `abort`. Those three match when the caller does not resume. A session that redid or failed a goal from the menu cannot be reproduced. HTTP has no place to read the menu.

**The interpreter recurs, and the JVM stack is finite.** `km-int` is not in tail position. It dereferences, removes duplicates, and traces around the recursive call. A recursive rule that Lisp answers can overflow the JVM. The port counts depth and, past 400, returns the failure a set `*km-depth-limit*` would return. Lisp leaves that limit unset. The number 400 can be raised. Some ceiling remains, because the stack does not grow without a bound. A binding cycle is the same fact with no answer on either side. The Lisp loops. The port throws and returns the knowledge base. [The frame store](migration/03-the-frame-store.md) records the throw. Looping would still not return the list the Lisp does not return.

**Frames are a value, not a property list.** Lisp stores slots on the symbol and keeps specials such as `*curr-situation*` for the whole image. The port stores the knowledge base in the value the caller passes. One caller uses a given value at a time. That is why the prompt and the HTTP service do not see each other, and why a lazy sequence is not mixed with a store update. Two consequences follow. A Lisp `nconc`, `delete`, or `setf` of a `car` changes every slot that shares that cons. A persistent update changes the slot that was written. A knowledge base that depends on the shared tail diverges, and preserving the alias would give up the value. `km` returns one value, or four when something went wrong. The port always returns one map. `:value` is the answer list. `:errors`, `:error-structures`, and `:warnings` are the other three. The prompt prints the answer and then the warning line. The call shape is the map. The answer list is the list.

**Symbols, `nil`, and case are different objects.** Lisp `eq` is identity of an interned symbol. Each read here builds a new symbol, so `identical?` is not name equality. `eql?` compares the name, and queries use that. What cannot match is a program that distinguishes two interned objects with one name, or a Lisp image that folded every symbol to uppercase while loading. This reader keeps case. `t` and `T` differ, which is the case-preserving reader. The empty list and false are one object in Lisp. In Clojure `()` is true and `nil` is the empty answer. The port uses one emptiness test, the equivalent of `km-null`, wherever the Lisp uses a value list as a Boolean. The symbol `nil` and the symbol `t` stay symbols. A cons cell is a record, and a record answers `map?`. Every test that accepts a map checks for a cons cell first. That check is the representation. Dropping it would treat a list as a frame.

**Floats and clocks are different machines.** Integers grow, and an exact ratio stays a ratio, including `1/2`. A float is a Java double. The Lisp default is a single float, and `~,Ne` leaves a halfway case up to the implementation. The values the notes name match: `0.0001` is `1.000e-4` and `-0.5` is `-5.000e-1`. A value on a rounding boundary can still differ. `km-equal` treats a gap inside `0.0001` as the same number, and a gap outside it as different. The statistics line takes its seconds from `System/nanoTime`. The Lisp uses `get-internal-run-time`. The words match. The seconds, and the lips and kaps counts that divide by those seconds, are the clock of the run. `(now)` in a save is that same kind of clock. Two Lisp saves of one image already differ because of it.

**There is no single Lisp order or Lisp encoding to copy.** `get-all-objects` walks an `eq` hash table. That order already differs between Lisp implementations. The port walks insertion order. `(taxonomy)` sorts each level with `string<`. Each save group and the comments section sort with `string-lessp`. Stored slot order stays the order `add-val` wrote, and `(the1 ...)` reads that. A character's lower case follows the Java rule for one character, so a match does not depend on the locale. Lisp `char-downcase` can differ for a character outside that rule. An ASCII name matches. Lisp opens a `.km` file in the implementation's default encoding. The port reads UTF-8, and bytes that are not UTF-8 are read as ISO-8859-1. A file in a third encoding can change a string. No encoding is the encoding of every Lisp.

**The wire format is JSON.** A proper list is an array. A symbol is an object. A ratio is text. An integer that fits in a long is a number, and a larger integer is decimal text. [The interpreter](migration/06-the-interpreter.md) records that body. The route returns the same answer list the prompt prints. The bytes are the encoding of the map, which Lisp does not produce. The `apply` argument limit in `strings.lisp` is a Lisp workaround. The JVM does not need it, and the joined string is the same string.

## What the wrap-up already aligned

The ten steps in [the outcome review](port-outcome-review.md) are the differences a later note took back: ordinary instances, definitions, rule bodies, edits and position, stored flags, one survivor, the same explanation, the same file, the remaining commands, and the small texts. `(pluralize ...)` stays the KM 2.5.45 error. One handler table is the interpreter. `compiled-handlers.lisp` and `compiler.lisp` stay out. `htextify` returns nothing, and ordinary `(taxonomy)` does not ask it for HTML. The corpus comparison named in that review is still the acceptance condition: a corpus of `.km` files loads, and a fixed set of queries agrees on the answer list under `km-equal`, on which frames are instances of each class, and on `(why)` where the corpus records an explanation. The two lists above are what that comparison is allowed to show.
